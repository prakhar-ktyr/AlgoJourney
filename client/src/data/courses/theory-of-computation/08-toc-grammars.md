# Formal Grammars

A **formal grammar** is a set of rules for generating strings in a language. If you think of a language as a set of "legal sentences," then a grammar tells you exactly how to build those sentences, symbol by symbol.

Grammars are everywhere: programming language syntax (C, Python, JavaScript), natural language structure (English, Hindi), data formats (JSON, XML), and mathematical expressions. In the Theory of Computation, grammars provide the **generative** perspective on languages — while automata provide the **recognition** perspective.

---

## What Is a Grammar?

Informally, a grammar consists of:

1. **Variables** (non-terminals): placeholders that get replaced during string generation
2. **Terminals**: the actual symbols that appear in the final string
3. **Production rules**: instructions for replacing variables with combinations of variables and terminals
4. **Start symbol**: the variable where generation begins

### A Simple Example

Consider the grammar with rules:

$$S \to aSb$$
$$S \to \varepsilon$$

Starting from $S$, we can derive:
- $S \Rightarrow \varepsilon$ (the empty string)
- $S \Rightarrow aSb \Rightarrow a\varepsilon b = ab$
- $S \Rightarrow aSb \Rightarrow aaSbb \Rightarrow aa\varepsilon bb = aabb$
- $S \Rightarrow aSb \Rightarrow aaSbb \Rightarrow aaaSbbb \Rightarrow aaa\varepsilon bbb = aaabbb$

This grammar generates the language $L = \{a^n b^n \mid n \geq 0\}$.

## Formal Definition

A **grammar** is a 4-tuple:

$$G = (V, \Sigma, R, S)$$

where:

| Component | Name | Description |
|---|---|---|
| $V$ | Variables (non-terminals) | Finite set of symbols used during derivation |
| $\Sigma$ | Terminals (alphabet) | Finite set of symbols in the generated strings |
| $R$ | Production rules | Finite set of replacement rules |
| $S$ | Start symbol | A distinguished variable in $V$ where derivation begins |

### Constraints

- $V$ and $\Sigma$ are disjoint: $V \cap \Sigma = \emptyset$
- $S \in V$ (the start symbol must be a variable)
- Each rule in $R$ has the form $\alpha \to \beta$ where:
  - $\alpha$ contains at least one variable (left side)
  - $\beta$ is a string of variables and/or terminals (right side)

### Notation Conventions

- **Uppercase letters** ($A, B, C, S$) represent variables
- **Lowercase letters** ($a, b, c$) represent terminals
- **Greek letters** ($\alpha, \beta, \gamma$) represent strings of variables and terminals
- $\to$ separates left and right sides of a production
- $\mid$ denotes alternatives: $A \to \alpha \mid \beta$ means $A \to \alpha$ and $A \to \beta$

## Derivation

A **derivation** is the process of generating a string by repeatedly applying production rules.

### One-Step Derivation ($\Rightarrow$)

We write $\alpha A \beta \Rightarrow \alpha \gamma \beta$ if there is a rule $A \to \gamma$ in $R$. This means: replace one occurrence of variable $A$ in the string with $\gamma$.

### Multi-Step Derivation ($\Rightarrow^*$)

We write $\alpha \Rightarrow^* \beta$ if $\beta$ can be obtained from $\alpha$ by zero or more derivation steps:

$$\alpha \Rightarrow \gamma_1 \Rightarrow \gamma_2 \Rightarrow \cdots \Rightarrow \beta$$

Note: $\alpha \Rightarrow^* \alpha$ always holds (zero steps).

### Example Derivation

Grammar: $S \to aSb \mid \varepsilon$

$$S \Rightarrow aSb \Rightarrow aaSbb \Rightarrow aaaSbbb \Rightarrow aaa\varepsilon bbb = aaabbb$$

We write: $S \Rightarrow^* aaabbb$

---

## Language Generated by a Grammar

The **language generated** by grammar $G$, written $L(G)$, is:

$$L(G) = \{w \in \Sigma^* \mid S \Rightarrow^* w\}$$

In words: $L(G)$ is the set of all terminal strings that can be derived from the start symbol $S$.

> **Key point:** The derived string $w$ must consist entirely of terminals — no variables remain.

## Example Grammars

### Example 1: $L = \{a^n b^n \mid n \geq 0\}$

$$G = (\{S\}, \{a, b\}, R, S)$$
$$R: \quad S \to aSb \mid \varepsilon$$

**Proof that $L(G) = \{a^n b^n \mid n \geq 0\}$:**

By induction, after $n$ applications of $S \to aSb$: $S \Rightarrow^* a^n S b^n$

Then applying $S \to \varepsilon$: $a^n S b^n \Rightarrow a^n \varepsilon b^n = a^n b^n$.

No other strings can be derived (every step either wraps $S$ in $a \ldots b$ or eliminates $S$).

### Example 2: $L = \{a^n b^m \mid n, m \geq 0\}$

$$G = (\{S, A, B\}, \{a, b\}, R, S)$$
$$R: \quad S \to AB$$
$$\phantom{R: \quad} A \to aA \mid \varepsilon$$
$$\phantom{R: \quad} B \to bB \mid \varepsilon$$

$A$ generates any number of $a$'s, $B$ generates any number of $b$'s, and $S$ puts them in sequence.

### Example 3: $L = \{w \in \{a, b\}^* \mid w = w^R\}$ (Palindromes)

$$G = (\{S\}, \{a, b\}, R, S)$$
$$R: \quad S \to aSa \mid bSb \mid a \mid b \mid \varepsilon$$

- $S \to aSa$ and $S \to bSb$ build symmetric outer layers
- $S \to a$, $S \to b$, and $S \to \varepsilon$ handle the center

### Example 4: Balanced Parentheses

$$G = (\{S\}, \{(, )\}, R, S)$$
$$R: \quad S \to SS \mid (S) \mid \varepsilon$$

- $S \to (S)$: wrap a balanced expression in parentheses
- $S \to SS$: concatenate two balanced expressions
- $S \to \varepsilon$: the empty string is balanced

Derivation of `(())()`:

$$S \Rightarrow SS \Rightarrow (S)S \Rightarrow ((S))S \Rightarrow (())S \Rightarrow (())(S) \Rightarrow (())()$$

### Example 5: Simple Arithmetic Expressions

$$G = (\{E, T, F\}, \{+, \times, (, ), \textbf{id}\}, R, E)$$
$$R: \quad E \to E + T \mid T$$
$$\phantom{R: \quad} T \to T \times F \mid F$$
$$\phantom{R: \quad} F \to (E) \mid \textbf{id}$$

This grammar generates arithmetic expressions with correct operator precedence ($\times$ binds tighter than $+$).

## The Chomsky Hierarchy

Noam Chomsky (1956) classified grammars into four types based on the form of their production rules. Each type generates a strictly larger class of languages.

### Type 3: Regular Grammars

**Rule form (right-linear):** $A \to aB$ or $A \to a$ or $A \to \varepsilon$

where $A, B \in V$ and $a \in \Sigma$.

Alternatively, **left-linear:** $A \to Ba$ or $A \to a$ or $A \to \varepsilon$

(Use one form consistently — don't mix left and right linear in the same grammar.)

**Recognized by:** Finite Automata (DFA/NFA)

**Example:** $L = \{a^n b \mid n \geq 0\}$

$$S \to aS \mid b$$

### Type 2: Context-Free Grammars (CFG)

**Rule form:** $A \to \alpha$

where $A \in V$ is a single variable and $\alpha \in (V \cup \Sigma)^*$ is any string of variables and terminals.

The key constraint: the left side is always a **single variable**. The replacement happens regardless of the surrounding context (hence "context-free").

**Recognized by:** Pushdown Automata (PDA)

**Examples:** $\{a^n b^n\}$, palindromes, balanced parentheses, arithmetic expressions.

### Type 1: Context-Sensitive Grammars (CSG)

**Rule form:** $\alpha A \beta \to \alpha \gamma \beta$

where $A \in V$, $\alpha, \beta \in (V \cup \Sigma)^*$, and $\gamma \in (V \cup \Sigma)^+$ (non-empty).

The variable $A$ is replaced by $\gamma$, but **only in the context** of being surrounded by $\alpha$ and $\beta$. Also, $|\alpha A \beta| \leq |\alpha \gamma \beta|$ (the string never shrinks).

**Recognized by:** Linear Bounded Automata (LBA)

**Example:** $L = \{a^n b^n c^n \mid n \geq 1\}$ (not context-free!)

### Type 0: Unrestricted Grammars

**Rule form:** $\alpha \to \beta$

where $\alpha$ contains at least one variable. No restrictions on $\beta$ (it can even be shorter than $\alpha$).

**Recognized by:** Turing Machines

**Generates:** Recursively Enumerable Languages

### The Hierarchy

$$\text{Type 3} \subset \text{Type 2} \subset \text{Type 1} \subset \text{Type 0}$$

| Type | Grammar | Automaton | Language Class |
|---|---|---|---|
| 3 | Regular | Finite Automaton | Regular Languages |
| 2 | Context-Free | Pushdown Automaton | Context-Free Languages |
| 1 | Context-Sensitive | Linear Bounded Automaton | Context-Sensitive Languages |
| 0 | Unrestricted | Turing Machine | Recursively Enumerable |

Each inclusion is **strict** — there exist languages in each class that are NOT in the class below it.

**Separating examples:**
- $\{a^n b^n \mid n \geq 0\}$ is context-free but not regular
- $\{a^n b^n c^n \mid n \geq 0\}$ is context-sensitive but not context-free
- The halting problem language is r.e. but not context-sensitive

## Parse Trees (Derivation Trees)

A **parse tree** (or derivation tree) is a graphical representation of a derivation. It shows the hierarchical structure of how a string was generated.

### Structure

- **Root:** The start symbol $S$
- **Internal nodes:** Variables
- **Leaves:** Terminals or $\varepsilon$
- **Children of a node $A$:** If rule $A \to X_1 X_2 \cdots X_k$ is applied, then $A$'s children (left to right) are $X_1, X_2, \ldots, X_k$

### Yield

The **yield** of a parse tree is the string obtained by reading the leaves from left to right. This is the string derived.

### Example

Grammar: $E \to E + T \mid T$, $T \to T \times F \mid F$, $F \to (E) \mid \textbf{id}$

Parse tree for $\textbf{id} + \textbf{id} \times \textbf{id}$:

```
        E
       /|\
      E + T
      |  /|\
      T T × F
      |  |   |
      F  F  id
      |  |
     id id
```

The tree makes the structure explicit: multiplication binds tighter than addition.

## Leftmost and Rightmost Derivations

For context-free grammars, when multiple variables exist in a sentential form, we can choose which to expand first.

### Leftmost Derivation

Always expand the **leftmost** variable first.

**Example:** Grammar $S \to AB$, $A \to a$, $B \to b$

$$S \Rightarrow_{lm} AB \Rightarrow_{lm} aB \Rightarrow_{lm} ab$$

### Rightmost Derivation

Always expand the **rightmost** variable first.

$$S \Rightarrow_{rm} AB \Rightarrow_{rm} Ab \Rightarrow_{rm} ab$$

### Important Facts

- Every parse tree corresponds to exactly one leftmost derivation and one rightmost derivation
- A grammar is **ambiguous** if some string has two different parse trees (equivalently, two different leftmost derivations)

### Ambiguity Example

Grammar: $E \to E + E \mid E \times E \mid \textbf{id}$

The string $\textbf{id} + \textbf{id} \times \textbf{id}$ has two parse trees:

**Tree 1** (multiplication first):
```
      E
     /|\
    E + E
    |  /|\
   id E × E
      |   |
     id  id
```

**Tree 2** (addition first):
```
      E
     /|\
    E × E
   /|\   |
  E + E  id
  |   |
 id  id
```

This grammar is ambiguous! The earlier grammar with $E, T, F$ resolves this ambiguity.

## Why Grammars Matter

### Compilers

Every programming language has a formal grammar (usually context-free). The parser in a compiler uses this grammar to build a parse tree (or abstract syntax tree) from source code.

```
// JavaScript grammar rule (simplified):
IfStatement → "if" "(" Expression ")" Statement
            | "if" "(" Expression ")" Statement "else" Statement
```

### Natural Language Processing

Grammars model the structure of human language:

```
Sentence → NounPhrase VerbPhrase
NounPhrase → Determiner Noun
VerbPhrase → Verb NounPhrase
```

### Data Formats

JSON, XML, HTML, and other structured data formats are defined by context-free grammars.

### Theoretical Significance

- Grammars define what is **computable** at different levels
- The Chomsky hierarchy connects language theory to computability theory
- Undecidable problems arise: "Does this grammar generate all strings?" is undecidable for CFGs

## Exercises

### Exercise 1

Write a context-free grammar for $L = \{a^m b^n \mid m > n \geq 0\}$.

<details>
<summary><strong>Solution</strong></summary>

$$S \to aS \mid aB$$
$$B \to aBb \mid \varepsilon$$

Alternatively:
$$S \to AS'$$
$$S' \to aS'b \mid \varepsilon$$
$$A \to aA \mid a$$

The idea: generate at least one extra $a$ (via $S \to aS$ or $A$), then generate matching $a^n b^n$ pairs.

Simpler version:
$$S \to aSb \mid aS \mid a$$

- $S \to aSb$: generate matching pair
- $S \to aS$: generate extra $a$
- $S \to a$: base case (at least one extra $a$)

</details>

### Exercise 2

Give a grammar for the language of all strings over $\{a, b\}$ with twice as many $a$'s as $b$'s.

<details>
<summary><strong>Solution</strong></summary>

$$S \to \varepsilon \mid SaaSb \mid SaSab \mid SbSaa \mid SaSba \mid SbaSa \mid SbaaSS$$

A cleaner approach — think of it as: every $b$ must be "balanced" by two $a$'s:

$$S \to SS \mid aaSb \mid aSab \mid Saab \mid abSa \mid aSba \mid bSaa \mid \varepsilon$$

The key idea: any string with $|w|_a = 2|w|_b$ can be built by interleaving two $a$'s with each $b$ in all possible relative positions.

</details>

### Exercise 3

Classify each grammar by its Chomsky hierarchy type:

(a) $S \to aS \mid bA$, $A \to a$

(b) $S \to aSb \mid \varepsilon$

(c) $aS \to aabS$, $S \to \varepsilon$

<details>
<summary><strong>Solution</strong></summary>

(a) **Type 3 (Regular):** All rules have a single variable on the left and are right-linear ($A \to aB$ or $A \to a$).

(b) **Type 2 (Context-Free):** Each rule has a single variable on the left ($S \to \alpha$).

(c) **Type 1 (Context-Sensitive):** The rule $aS \to aabS$ has context on the left side ($a$ is the left context). Also, $|aS| = 2 \leq 4 = |aabS|$, so the string doesn't shrink. (Exception: $S \to \varepsilon$ technically violates CSG form, but is allowed if $S$ doesn't appear on any right side.)

</details>

### Exercise 4

Show that the grammar $S \to SS \mid (S) \mid \varepsilon$ is ambiguous.

<details>
<summary><strong>Solution</strong></summary>

Consider the string `()()`. It has two leftmost derivations:

**Derivation 1:**
$$S \Rightarrow SS \Rightarrow (S)S \Rightarrow ()S \Rightarrow ()(S) \Rightarrow ()()$$

**Derivation 2:**
$$S \Rightarrow SS \Rightarrow SSS \Rightarrow (S)SS \Rightarrow ()SS \Rightarrow ()(S)S \Rightarrow ()()S \Rightarrow ()()$$

Wait — let's be more careful. Two different **parse trees**:

**Tree 1:** $S \to SS$ where first $S \to (S) \to ()$ and second $S \to (S) \to ()$.

**Tree 2:** $S \to SS$ where first $S \to SS \to (S)(S) \to ()()$ and second $S \to \varepsilon$... 

Actually the clearest example: $S \Rightarrow SS$, and the split point of $()()$ into two parts is ambiguous: it could be $()()|_\varepsilon$ via $S \to SS$ where first $S$ derives $()()$ differently.

The simplest proof: The string $()()()$ has two parse trees (splitting as $[()][()()]$ vs $[()()][()]$). $\square$

</details>

### Exercise 5

Write a regular (Type 3) grammar for the language of binary strings ending in $01$.

<details>
<summary><strong>Solution</strong></summary>

$$S \to 0S \mid 1S \mid 0A$$
$$A \to 1$$

- $S$ allows reading any number of $0$s and $1$s
- When we see a $0$ we can "guess" it starts the final $01$ pattern by going to $A$
- $A$ expects exactly one more $1$ and then accepts

This is right-linear (Type 3). $\square$

</details>

### Exercise 6

Construct a grammar for $L = \{a^i b^j c^k \mid i = j \text{ or } j = k\}$.

<details>
<summary><strong>Solution</strong></summary>

Since $L = L_1 \cup L_2$ where $L_1 = \{a^n b^n c^k\}$ and $L_2 = \{a^i b^n c^n\}$:

$$S \to S_1 \mid S_2$$

For $L_1 = \{a^n b^n c^k \mid n, k \geq 0\}$:
$$S_1 \to AB$$
$$A \to aAb \mid \varepsilon$$
$$B \to cB \mid \varepsilon$$

For $L_2 = \{a^i b^n c^n \mid i, n \geq 0\}$:
$$S_2 \to CD$$
$$C \to aC \mid \varepsilon$$
$$D \to bDc \mid \varepsilon$$

</details>

## Summary

- A grammar $G = (V, \Sigma, R, S)$ generates strings by applying production rules starting from $S$
- The language $L(G)$ is the set of all terminal strings derivable from $S$
- The Chomsky hierarchy classifies grammars (and languages) into four types
- Parse trees visualize derivation structure
- Ambiguous grammars have multiple parse trees for some string
- Grammars are the foundation of compiler design, NLP, and formal language theory
