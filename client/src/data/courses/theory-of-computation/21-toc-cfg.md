# Context-Free Grammars

Context-Free Grammars (CFGs) are a powerful formalism for describing languages that go beyond what finite automata can recognize. They form the backbone of programming language syntax and are essential in compiler design.

---

## Why Context-Free Grammars?

Regular languages (recognized by DFAs/NFAs) cannot handle nested structures. For example:

- Balanced parentheses: $\{(^n)^n \mid n \geq 0\}$
- Matching tags: `<div>...</div>`
- Equal counts: $\{a^n b^n \mid n \geq 0\}$

The pumping lemma for regular languages proves these are **not** regular. We need a more expressive formalism — **Context-Free Grammars**.

---

## Formal Definition

A **Context-Free Grammar** is a 4-tuple:

$$G = (V, \Sigma, R, S)$$

where:

| Component | Description |
|-----------|-------------|
| $V$ | A finite set of **variables** (non-terminals) |
| $\Sigma$ | A finite set of **terminals** (alphabet), where $V \cap \Sigma = \emptyset$ |
| $R$ | A finite set of **production rules** of the form $A \to \alpha$ where $A \in V$ and $\alpha \in (V \cup \Sigma)^*$ |
| $S$ | The **start variable**, $S \in V$ |

The key restriction that makes a grammar "context-free" is that the left-hand side of every rule is a **single variable**. The variable can be replaced regardless of the surrounding context.

---

## Example: The Language $a^n b^n$

Consider the language $L = \{a^n b^n \mid n \geq 0\}$. This includes strings like $\varepsilon, ab, aabb, aaabbb, \ldots$

The CFG is:

$$G = (\{S\}, \{a, b\}, R, S)$$

where the rules $R$ are:

$$S \to aSb \mid \varepsilon$$

**How it works:**

- $S \Rightarrow \varepsilon$ (when $n = 0$)
- $S \Rightarrow aSb \Rightarrow aabb$ (when $n = 2$, applying $S \to aSb$ then $S \to \varepsilon$... wait, let's be careful)
- $S \Rightarrow aSb \Rightarrow ab$ (apply $S \to \varepsilon$ inside)
- $S \Rightarrow aSb \Rightarrow aaSbb \Rightarrow aabb$ (apply $S \to \varepsilon$ inside)

Each application of $S \to aSb$ adds one $a$ on the left and one $b$ on the right, guaranteeing equal counts.

## Derivations

A **derivation** is a sequence of rule applications that transforms the start variable into a string of terminals.

### Notation

- $\Rightarrow$: one step of derivation (apply one rule)
- $\Rightarrow^*$: zero or more steps of derivation
- $\alpha \Rightarrow \beta$: string $\beta$ is obtained from $\alpha$ by replacing one variable with the right-hand side of one of its rules

### The Language of a Grammar

The language generated by grammar $G$ is:

$$L(G) = \{w \in \Sigma^* \mid S \Rightarrow^* w\}$$

That is, all strings of terminals that can be derived from the start variable.

---

## Leftmost and Rightmost Derivations

When a sentential form has multiple variables, we must choose which to expand. Two canonical orders exist:

### Leftmost Derivation

Always expand the **leftmost** variable first. Denoted $\Rightarrow_{lm}$.

### Rightmost Derivation

Always expand the **rightmost** variable first. Denoted $\Rightarrow_{rm}$.

### Example

Consider the grammar for arithmetic expressions:

$$E \to E + T \mid T$$
$$T \to T * F \mid F$$
$$F \to (E) \mid id$$

**Derive** $id + id * id$:

**Leftmost derivation:**

$$E \Rightarrow_{lm} E + T \Rightarrow_{lm} T + T \Rightarrow_{lm} F + T \Rightarrow_{lm} id + T$$
$$\Rightarrow_{lm} id + T * F \Rightarrow_{lm} id + F * F \Rightarrow_{lm} id + id * F \Rightarrow_{lm} id + id * id$$

**Rightmost derivation:**

$$E \Rightarrow_{rm} E + T \Rightarrow_{rm} E + T * F \Rightarrow_{rm} E + T * id$$
$$\Rightarrow_{rm} E + F * id \Rightarrow_{rm} E + id * id \Rightarrow_{rm} T + id * id$$
$$\Rightarrow_{rm} F + id * id \Rightarrow_{rm} id + id * id$$

Both derivations produce the same string, but in different orders. For an unambiguous grammar, there is exactly **one** leftmost derivation and **one** rightmost derivation for each string in the language.

## Parse Trees

A **parse tree** (or derivation tree) is a graphical representation of a derivation.

### Properties of a Parse Tree

1. The **root** is labeled with the start variable $S$
2. Each **interior node** is labeled with a variable from $V$
3. Each **leaf** is labeled with a terminal from $\Sigma$ or $\varepsilon$
4. If node $A$ has children $X_1, X_2, \ldots, X_k$, then $A \to X_1 X_2 \cdots X_k$ is a production rule in $R$
5. If node $A$ has a single child labeled $\varepsilon$, then $A \to \varepsilon$ is a rule and $\varepsilon$ is the only child

### Yield of a Parse Tree

The **yield** is the string obtained by reading the leaves from left to right. The yield is the string derived by the grammar.

### Example Parse Tree

For the derivation of $id + id * id$ using the expression grammar:

```
         E
       / | \
      E  +  T
      |    /|\
      T   T * F
      |   |   |
      F   F  id
      |   |
     id  id
```

The yield is: $id + id * id$

## Sentential Forms

A **sentential form** is any string $\alpha \in (V \cup \Sigma)^*$ such that $S \Rightarrow^* \alpha$.

- If $\alpha$ contains only terminals ($\alpha \in \Sigma^*$), it is a **sentence** of the language.
- If $\alpha$ contains at least one variable, it is a proper sentential form (not yet a complete string in the language).

## More CFG Examples

### Example 1: Palindromes over $\{a, b\}$

$$L = \{w \in \{a,b\}^* \mid w = w^R\}$$

Grammar:

$$S \to aSa \mid bSb \mid a \mid b \mid \varepsilon$$

**Explanation:**

- $S \to aSa$: wraps an $a$ on both sides
- $S \to bSb$: wraps a $b$ on both sides
- $S \to a$: odd-length palindrome with center $a$
- $S \to b$: odd-length palindrome with center $b$
- $S \to \varepsilon$: even-length palindrome (empty center)

**Sample derivation** for $abba$:

$$S \Rightarrow aSa \Rightarrow abSba \Rightarrow abba$$

(using $S \to bSb$ then $S \to \varepsilon$)

---

### Example 2: Balanced Parentheses

$$L = \{w \in \{(, )\}^* \mid w \text{ is balanced}\}$$

Grammar:

$$S \to SS \mid (S) \mid \varepsilon$$

**Explanation:**

- $S \to SS$: concatenation of two balanced strings
- $S \to (S)$: wrap balanced string in matching parentheses
- $S \to \varepsilon$: empty string is balanced

**Sample derivation** for $(()())$:

$$S \Rightarrow (S) \Rightarrow (SS) \Rightarrow ((S)S) \Rightarrow ((S)(S)) \Rightarrow (()()) $$

---

### Example 3: Arithmetic Expressions

A more complete grammar with numbers and operators:

$$E \to E + E \mid E - E \mid E * E \mid E / E \mid (E) \mid num$$

This grammar is **ambiguous** (we will study this in a later lesson), but it captures the structure of arithmetic expressions.

---

### Example 4: $\{a^i b^j c^k \mid i = j \text{ or } j = k\}$

This language requires a union construction:

$$S \to S_1 \mid S_2$$
$$S_1 \to S_1 c \mid A$$
$$A \to aAb \mid \varepsilon$$
$$S_2 \to aS_2 \mid B$$
$$B \to bBc \mid \varepsilon$$

**Explanation:**

- $S_1$ generates $a^n b^n c^*$ (equal $a$'s and $b$'s, any number of $c$'s)
- $S_2$ generates $a^* b^n c^n$ (any number of $a$'s, equal $b$'s and $c$'s)
- Together they generate the union

---

### Example 5: Strings with More $a$'s than $b$'s

$$L = \{w \in \{a,b\}^* \mid |w|_a > |w|_b\}$$

Grammar:

$$S \to SA \mid A$$
$$A \to aAb \mid bAa \mid aA \mid a$$

**Intuition:** $A$ generates strings with exactly one more $a$ than $b$'s. $S$ concatenates one or more such blocks.

## CFG Design Strategies

### Strategy 1: Recursive Structure

Identify the recursive structure of the language. If strings can be built by wrapping:

$$S \to aSb$$

If strings can be built by concatenation:

$$S \to AB$$

### Strategy 2: Divide and Conquer

Break the language into cases and handle each with a separate variable:

$$S \to S_1 \mid S_2 \mid \cdots \mid S_k$$

### Strategy 3: Build from Regular Operations

- **Union**: $S \to S_1 \mid S_2$
- **Concatenation**: $S \to S_1 S_2$
- **Star**: $S \to SS_1 \mid \varepsilon$

### Strategy 4: Match Symbols

When symbols must be matched (like in $a^n b^n$), use a variable that generates matched pairs:

$$S \to aSb$$

### Strategy 5: Count Arguments

For languages involving counting:

- Equal counts: generate in pairs ($S \to aSb$)
- More of one: generate extras and pairs ($S \to aS \mid aSb \mid a$)

## Conventions and Notation

| Symbol | Meaning |
|--------|---------|
| $A, B, C, \ldots, S$ | Variables (uppercase) |
| $a, b, c, \ldots$ | Terminals (lowercase) |
| $\alpha, \beta, \gamma$ | Strings in $(V \cup \Sigma)^*$ |
| $u, v, w, x, y, z$ | Strings in $\Sigma^*$ (terminal strings) |
| $\varepsilon$ | Empty string |
| $\Rightarrow$ | Derives in one step |
| $\Rightarrow^*$ | Derives in zero or more steps |

## CFGs vs Regular Languages

Every regular language is context-free, but not vice versa.

**Theorem:** If $L$ is a regular language, then there exists a CFG $G$ such that $L(G) = L$.

**Proof sketch:** Given a DFA $(Q, \Sigma, \delta, q_0, F)$, construct a CFG where:

- Variables = states of the DFA
- Start variable = $q_0$
- For each transition $\delta(q_i, a) = q_j$, add rule $q_i \to a \cdot q_j$
- For each accepting state $q_f \in F$, add rule $q_f \to \varepsilon$

This gives a **right-linear grammar**, which is a special case of CFG.

---

## Context-Free Languages

A language $L$ is **context-free** if there exists a CFG $G$ such that $L(G) = L$.

The class of context-free languages (CFLs) properly contains the class of regular languages:

$$\text{Regular} \subset \text{Context-Free} \subset \text{All Languages}$$

Examples of CFLs that are not regular:

- $\{a^n b^n \mid n \geq 0\}$
- $\{ww^R \mid w \in \{a,b\}^*\}$ (even-length palindromes)
- Balanced parentheses
- $\{a^i b^j c^k \mid i + j = k\}$

## Closure Properties of CFLs

Context-free languages are closed under several operations:

| Operation | Closed? | Construction |
|-----------|---------|--------------|
| Union | ✓ | $S \to S_1 \mid S_2$ |
| Concatenation | ✓ | $S \to S_1 S_2$ |
| Kleene star | ✓ | $S \to SS_1 \mid \varepsilon$ |
| Intersection | ✗ | $\{a^n b^n c^m\} \cap \{a^m b^n c^n\} = \{a^n b^n c^n\}$ (not CFL) |
| Complement | ✗ | By De Morgan: if closed under $\cap$ and $\cup$, would imply $\cap$ closure |
| Intersection with regular | ✓ | Product construction (PDA $\times$ DFA) |
| Homomorphism | ✓ | Replace terminals in grammar |
| Inverse homomorphism | ✓ | PDA construction |
| Reversal | ✓ | Reverse all rule RHS |

### Union Construction

Given grammars $G_1 = (V_1, \Sigma, R_1, S_1)$ and $G_2 = (V_2, \Sigma, R_2, S_2)$ with $V_1 \cap V_2 = \emptyset$:

$$G = (V_1 \cup V_2 \cup \{S\}, \Sigma, R_1 \cup R_2 \cup \{S \to S_1 \mid S_2\}, S)$$

### Concatenation Construction

$$G = (V_1 \cup V_2 \cup \{S\}, \Sigma, R_1 \cup R_2 \cup \{S \to S_1 S_2\}, S)$$

### Star Construction

Given $G_1 = (V_1, \Sigma, R_1, S_1)$:

$$G = (V_1 \cup \{S\}, \Sigma, R_1 \cup \{S \to SS_1 \mid \varepsilon\}, S)$$

## Equivalence: CFG and PDA

A fundamental theorem in formal language theory:

$$L \text{ is context-free} \iff L \text{ is recognized by some PDA}$$

This means:
- For every CFG, we can build an equivalent Pushdown Automaton
- For every PDA, we can build an equivalent CFG

We will study PDAs in detail in a later lesson.

## Applications of CFGs

### Programming Language Syntax

Most programming languages define their syntax using CFGs (often in BNF or EBNF notation):

```
<expr> ::= <expr> "+" <term> | <term>
<term> ::= <term> "*" <factor> | <factor>
<factor> ::= "(" <expr> ")" | <number>
```

### Natural Language Processing

CFGs model phrase structure in natural language:

```
<sentence> ::= <noun-phrase> <verb-phrase>
<noun-phrase> ::= <det> <noun> | <noun>
<verb-phrase> ::= <verb> <noun-phrase> | <verb>
```

### XML/HTML Validation

The nested tag structure of XML is context-free:

$$D \to \langle t \rangle D \langle /t \rangle \mid \text{text} \mid DD$$

### Compiler Design

- **Lexical analysis:** uses regular expressions (DFA/NFA)
- **Syntax analysis (parsing):** uses CFGs
- **Semantic analysis:** uses attribute grammars (extensions of CFGs)

## Summary

| Concept | Key Point |
|---------|-----------|
| CFG definition | $G = (V, \Sigma, R, S)$ with rules $A \to \alpha$ |
| Derivation | Sequence of rule applications from $S$ to a terminal string |
| Parse tree | Tree representation of a derivation |
| Leftmost derivation | Always expand leftmost variable |
| CFL | Language generated by some CFG |
| Regular $\subset$ CFL | Every regular language has a CFG |
| Closure | CFLs closed under $\cup$, concatenation, $*$, but NOT $\cap$ or complement |
| CFG $\equiv$ PDA | Context-free languages are exactly the PDA-recognizable languages |
