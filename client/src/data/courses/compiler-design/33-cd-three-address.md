# Three-Address Code

**Three-Address Code (TAC)** is the most widely used medium-level intermediate representation. Each TAC instruction contains **at most three addresses** (two operands and one result) and performs **at most one operation**.

---

## General Form

$$x = y \; \text{op} \; z$$

Where:
- $x$, $y$, $z$ are **addresses** — names, constants, or compiler-generated temporaries
- $\text{op}$ is an arithmetic, logical, or relational operator

The name "three-address" comes from the three operand positions, even though some instructions use fewer.

---

## Instruction Types

### 1. Assignment with Binary Operator

```
x = y op z
```

Examples:
```
t1 = a + b
t2 = t1 * c
t3 = i < n
```

### 2. Assignment with Unary Operator

```
x = op y
```

Examples:
```
t1 = -a
t2 = !flag
t3 = (float) i    // type conversion
```

### 3. Copy Assignment

```
x = y
```

Simply copies one value to another:
```
a = t1
temp = b
```

### 4. Unconditional Jump

```
goto L
```

Transfers control to the instruction labeled $L$.

### 5. Conditional Jump

```
if x goto L
ifFalse x goto L
if x relop y goto L
```

Examples:
```
if t1 goto L3
ifFalse t2 goto L5
if a < b goto L1
```

### 6. Function Call and Return

```
param x          // push parameter
call f, n        // call function f with n parameters
y = call f, n    // call with return value
return x         // return value x
```

Example — calling `result = max(a, b)`:
```
param a
param b
result = call max, 2
```

### 7. Indexed Assignment (Array Access)

```
x = y[i]     // load from array
x[i] = y     // store to array
```

Examples:
```
t1 = arr[i]       // t1 = arr[i]
arr[j] = t2       // arr[j] = t2
```

### 8. Pointer Operations

```
x = &y       // address-of
x = *y       // dereference (load)
*x = y       // dereference (store)
```

Examples:
```
t1 = &var        // t1 gets address of var
t2 = *ptr        // t2 gets value pointed to by ptr
*ptr = t3        // store t3 at address in ptr
```

## Temporary Variables

The compiler generates **temporary variables** (`t1`, `t2`, `t3`, ...) to hold intermediate results:

### Source Code

```c
x = (a + b) * (c - d);
```

### TAC

```
t1 = a + b
t2 = c - d
t3 = t1 * t2
x  = t3
```

Each sub-expression gets its own temporary. The compiler assigns them sequentially.

---

## Labels

Labels mark positions in the code that can be targets of jumps:

```
L1: t1 = a + 1
    if t1 < n goto L1
L2: ...
```

Labels are generated by the compiler: `L0`, `L1`, `L2`, ... They don't correspond to anything in the source code (unless the language has `goto`).

---

## Generating TAC for Expressions

The compiler traverses the AST recursively, generating TAC bottom-up:

### Algorithm

```python
def gen_expr(node):
    """Generate TAC for an expression node. Returns the address holding the result."""
    if node.is_leaf():
        # Variable or constant — no code needed
        return node.value

    if node.is_unary():
        arg = gen_expr(node.child)
        temp = new_temp()
        emit(f"{temp} = {node.op} {arg}")
        return temp

    if node.is_binary():
        left = gen_expr(node.left)
        right = gen_expr(node.right)
        temp = new_temp()
        emit(f"{temp} = {left} {node.op} {right}")
        return temp
```

### Complete Example

Source: `a + b * c - d`

AST (respecting precedence):
```
      -
     / \
    +   d
   / \
  a   *
     / \
    b   c
```

TAC generation (post-order traversal):
```
t1 = b * c      ← visit *
t2 = a + t1     ← visit +
t3 = t2 - d     ← visit -
```

## Example: Assignment Statement

Source: `x = a * b + c * d`

```
t1 = a * b
t2 = c * d
t3 = t1 + t2
x  = t3
```

Or more compactly (some compilers optimize the last copy away):
```
t1 = a * b
t2 = c * d
x  = t1 + t2
```

---

## Example: Function Call

Source: `result = compute(x + 1, y * 2)`

```
t1 = x + 1
t2 = y * 2
param t1
param t2
result = call compute, 2
```

---

## Example: Array Access

Source: `a[i] = b[j] + c`

Assuming element size is 4 bytes:
```
t1 = j * 4
t2 = b[t1]       // load b[j]
t3 = t2 + c
t4 = i * 4
a[t4] = t3       // store to a[i]
```

## Addressing Modes in TAC

TAC instructions can reference:

| Address Type | Example | Description |
|-------------|---------|-------------|
| Name | `a`, `count` | Source-level variable |
| Constant | `42`, `3.14` | Literal value |
| Temporary | `t1`, `t2` | Compiler-generated |
| Label | `L1`, `L5` | Jump target |

These are **abstract** addresses — the back-end maps them to registers or memory locations later.

---

## TAC vs Machine Code

| Feature | TAC | Machine Code |
|---------|-----|--------------|
| Registers | Unlimited temporaries | Fixed set |
| Operations | Abstract (`+`, `*`) | ISA-specific (`ADD`, `MUL`) |
| Memory | Named variables | Addresses/offsets |
| Control flow | Labels + goto | Branch instructions |

TAC assumes **infinite temporaries** — register allocation happens later.

## Implementation: Data Structures

### Quadruple Array

```c
typedef struct {
    char op[8];
    char arg1[32];
    char arg2[32];
    char result[32];
} Quad;

Quad code[MAX_INSTRUCTIONS];
int next_instr = 0;

void emit(char *op, char *a1, char *a2, char *res) {
    strcpy(code[next_instr].op, op);
    strcpy(code[next_instr].arg1, a1);
    strcpy(code[next_instr].arg2, a2);
    strcpy(code[next_instr].result, res);
    next_instr++;
}
```

### Generating Temporaries

```c
int temp_count = 0;

char* new_temp() {
    static char buf[16];
    sprintf(buf, "t%d", temp_count++);
    return strdup(buf);
}
```

### Generating Labels

```c
int label_count = 0;

char* new_label() {
    static char buf[16];
    sprintf(buf, "L%d", label_count++);
    return strdup(buf);
}
```

## Summary

| Concept | Key Point |
|---------|-----------|
| TAC form | `x = y op z` — at most one operator |
| Temporaries | Compiler-generated intermediate results |
| Labels | Named targets for jump instructions |
| Generation | Recursive AST traversal, bottom-up |
| Storage | Quadruples (most common), triples |

---

## Key Takeaways

1. TAC is a **linear** IR — easy to manipulate and optimize
2. Each instruction does **one operation** — simplifies analysis
3. **Temporaries** bridge complex expressions into simple steps
4. **Labels + goto** represent all control flow
5. TAC assumes **unlimited temporaries** — register allocation is separate
6. Generation follows **recursive descent** on the AST
